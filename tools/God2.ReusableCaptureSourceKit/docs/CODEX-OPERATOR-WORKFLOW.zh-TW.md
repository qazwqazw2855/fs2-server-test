# Codex 操作取證工作流程

## 固定分工

### 使用者只負責

1. 啟動需要的網路加速器。
2. 開啟遊戲官方登入器或遊戲。
3. 登入帳號並進入遊戲。
4. 依測試需求進行移動、戰鬥、施法、受擊與關閉遊戲。
5. 用短句回報目前階段。

### Codex 負責

1. 確認目前操作的是正確遊戲、路徑、版本與程序。
2. 使用隔離來源建置該遊戲的適配 DLL、控制器與解析器。
3. 在使用者啟動遊戲前準備提權主機及擷取工作階段。
4. 在獲授權的目標程序掛載 DLL，確認 ACK 與明文掛點狀態。
5. 持續監控 `PreEncrypt`、`PostDecrypt`、傳輸層、記憶體探針與事件佇列。
6. 遇到可自行修復的建置、路徑、程序時序或解析錯誤時主動修復，不把技術工作丟回使用者。
7. 使用者關閉遊戲後停止工作階段、排空事件、整理證據並輸出分析報告。
8. 清楚區分已驗證數值、候選數值、推論與缺少證據的欄位。
9. 將已驗證封包、記憶體與實機行為轉成服務端協議、戰鬥規則及內容實作。
10. 將已驗證的怪物、技能、物品、角色與公式資料寫入正式資料庫結構；不得用猜測值補空缺。
11. 建立可追溯的證據報告，保留 capture session、事件 sequence、公式輸入、結果及證據狀態。
12. 服務端或資料庫有變更時，負責 Release 建置、測試、發布、資料庫遷移、Build ID／manifest 及正式客戶端流程驗證。

## 固定口令

- 使用者說 `準備抓包`：Codex 完成程序、權限、建置產物、輸出目錄及控制器準備；未準備完成前不得叫使用者開始。
- Codex 說 `可以開始遊戲`：代表擷取控制器已就緒，正在等待正確目標程序。
- 使用者說 `已進遊戲`：Codex確認 DLL ACK、明文事件及工作階段身分。
- 使用者說 `開始測試`：Codex建立時間標記並開始關聯封包與記憶體事件。
- 使用者說 `測試完成`：Codex建立結束標記，但保持擷取直到遊戲關閉。
- 使用者說 `已關閉遊戲`：Codex停止、排空並分析，不要求使用者執行技術命令。

## 不得越界

1. 未經使用者明確授權，不修改官方登入器、遊戲安裝檔或其他專案。
2. 需要改 DLL 或控制器時，只修改該遊戲的隔離適配副本。
3. 不直接啟動遊戲，除非使用者明確要求 Codex 代為啟動。
4. 不用錯誤遊戲路徑、替代登入器或未驗證 DLL。
5. 不加入隱匿、反偵測或反作弊繞過功能。
6. 目標版本、函式簽章或程序身分不符時必須 fail closed。

## 新遊戲首次使用

首次適配時，Codex需要先完成：

1. 確認 `x86` 或 `x64`。
2. 建立精確版本身分與 SHA-256。
3. 找到並驗證 `PreEncrypt`、`PostDecrypt`。
4. 定義封包邊界、長度、Opcode、壓縮及加密順序。
5. 以 `GenericProbePlan` 驗證戰鬥函式與物件布局。
6. 完成受控自我測試後，才進行正式遊戲取證。

使用者不需要理解 RVA、注入器、記憶體偏移或解析程式；Codex應自行管理並只回報需要使用者在遊戲內執行的動作。

## 擷取到正式服務端的證據鏈

Codex應依序完成：

1. 擷取解密後封包、加密前封包及必要的受控記憶體事件。
2. 綁定角色、怪物、技能、目標、回合、傷害與獎勵事件。
3. 以多組受控實測排除隨機值、等級差、裝備、增益、減益與爆擊干擾。
4. 產生 `Verified`、`Derived`、`Candidate` 或 `EvidenceBlocked` 證據狀態。
5. 只有 `Verified` 或規則允許的 `Derived` 資料可以進入正式服務端與資料庫。
6. 完成服務端程式、資料庫 migration、測試與 Release 發布。
7. 使用正式外部啟動流程重新進遊戲驗證客戶端可見結果。

使用者在整條證據鏈中只負責登入遊戲及依 Codex 指示執行遊戲內動作；其餘工作全部由 Codex 負責。
